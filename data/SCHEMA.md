# Data files

Both files are generated by scripts in [`/scripts`](../scripts) and committed so the
site works with no runtime API calls. **Hand-editing is discouraged** — rerun the
builder instead. In particular, MP emails must come from the official source and must
never be constructed from a name pattern.

> **Status:** these are *seed* files containing one verified electorate (McEwen) so the
> site runs end-to-end. The full 150-MP and national-locality builds replace them — see
> the tasks in `HANDOFF.md`.

## `mps.json`

Object keyed by **electorate name** (exactly as the AEC spells it).

```json
{
  "McEwen": {
    "name": "Rob Mitchell",          // full name, no "MP" suffix
    "salutation": "Mr Mitchell",     // how the letter addresses them ("Dear ...")
    "email": "rob.mitchell.mp@aph.gov.au",  // published value, never constructed
    "state": "VIC",                  // NSW VIC QLD SA WA TAS NT ACT
    "party": "Australian Labor Party"
  }
}
```

Source: Parliament of Australia published Members contact list (aph.gov.au).

## `localities.json`

Maps a **postcode → suburb → list of electorates**, so a voter who enters suburb +
postcode is resolved to one MP, or offered a choice when a locality is split across
electorates.

```json
{
  "3757": { "WHITTLESEA": ["McEwen"] },
  "3000": { "MELBOURNE": ["Melbourne"] }
}
```

- Suburb keys are **UPPERCASE**, matching how the lookup normalises user input.
- The electorate array lists every electorate the locality overlaps, ordered by share of
  the locality's area (largest first) where a locality is split.
- A single-element array resolves straight to one MP. A multi-element array makes the
  site show a choice of electorates plus a link to the AEC finder.

Source: ABS "Suburbs and Localities" boundaries intersected with the current AEC federal
electoral boundaries (the boundaries in force since the 2025 election). Both are free
downloads — their licences require attribution in the site footer.
